# BuckyOSApp 测试文档入口

测试采用“共用测试用例 + 两种执行入口”的结构。功能步骤和通过标准只维护一份，本地 Dev 测试与 PR 包测试分别规定被测版本如何产生和如何追溯。

## 选择执行入口

| 场景 | 执行文档 | 被测版本 |
| --- | --- | --- |
| 开发中验证当前工作区改动 | [本地 Dev 测试流程](./本地Dev测试流程.md) | 由当前代码直接构建的 Dev/debug 版本 |
| PR 合并后或提测验收 | [PR 构建包测试流程](./PR构建包测试流程.md) | [pvehost.local](http://pvehost.local/) 上包含目标 PR 的最新可用包 |

选定入口并准备好被测版本后，按以下共用文档执行：

- [测试流程](./测试流程.md)：全量测试用例、自动化等级和通过标准。
- [Android 端到端测试流程](./安卓端到端测试流程.md)：创建、导入、绑定、解绑和重新绑定 OOD 的共用步骤。
- [测试报告模板](./测试报告模板.md)：两类测试统一使用的报告字段。
- [测试目标](./测试目标.txt)：当前版本的测试目标摘要。

## 共同约定

- 每轮只能标记一种测试类型：`local-dev` 或 `pr-package`。
- 两类测试不得混用被测版本。PR 包测试不能用本地重新编译的包替代；本地 Dev 测试不能把 PVE 包当作当前工作区改动的结果。
- 所有运行证据统一保存在 `auto_test/runs/YYYYMMDD-HHMMSS/`。
- 完整助记词、明文密码、私钥、完整 `pwd_hash`、完整 Active Code 和完整 SN token 不得进入报告、截图或持久化测试文件。
- 功能步骤发生变化时优先修改共用测试用例，不在两个执行入口中复制完整操作步骤。
