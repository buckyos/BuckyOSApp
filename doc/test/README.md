# BuckyOSApp 测试文档入口

测试文档按“验证需求 → 版本入口 → 公共业务生命周期 → 平台执行动作 → 功能专项矩阵 → 报告”分层。验证需求从用户角度定义 BuckyOSApp 发布前必须证明的完整路径；公共业务步骤只维护一份，本地 Dev 与 PR 包入口只规定被测版本如何产生和追溯，Android 与 macOS 文档只维护各自的平台差异。

首先阅读 [E2E 验证需求](./E2E验证需求.md)，确定本次发布涉及的用户目标、路径优先级和发布门槛，再选择下面的执行入口。

## 选择执行入口

| 场景 | 执行文档 | 被测版本 |
| --- | --- | --- |
| 开发中验证当前工作区改动 | [本地 Dev 测试流程](./本地Dev测试流程.md) | 由当前代码直接构建的 Dev/debug 版本 |
| PR 合并后或提测验收 | [PR 构建包测试流程](./PR构建包测试流程.md) | [pvehost.local](http://pvehost.local/) 上包含目标 PR 的最新可用包 |

选定入口并准备好被测版本后，按以下共用文档执行：

- [E2E 验证需求](./E2E验证需求.md)：BuckyOSApp 的用户目标、完整路径、使用频次优先级和发布门槛。
- [测试流程](./测试流程.md)：全量测试用例、自动化等级和通过标准。
- [共用账户与 OOD 生命周期](./端到端/共用账户与OOD生命周期.md)：Android 与 macOS 共用的创建、导入、绑定、解绑、重置和重新绑定主链路，是端到端业务步骤的唯一来源。
- [Android 端到端执行流程](./端到端/Android执行流程.md)：Android 的包来源、全新安装、设备控制和平台专项检查。
- [macOS 端到端执行流程](./端到端/macOS执行流程.md)：目标 Mac 的原生架构组合 pkg、全新安装及 App/OOD 平台检查。
- [测试报告模板](./测试报告模板.md)：两类测试统一使用的报告字段。

## 共同约定

- 每轮只能标记一种测试类型：`local-dev` 或 `pr-package`。
- 两类测试不得混用被测版本。PR 包测试不能用本地重新编译的包替代；本地 Dev 测试不能把 PVE 包当作当前工作区改动的结果。
- 所有运行证据统一保存在 `auto_test/runs/YYYYMMDD-HHMMSS/`。
- 完整助记词、明文密码、私钥、完整 `pwd_hash`、完整 Active Code 和完整 SN token 不得进入报告、截图或持久化测试文件。
- 账户/OOD 主链路发生变化时只修改共用生命周期；平台安装或控制方式只修改对应平台文档；异常分支和技术断言只修改测试流程。
